# 05 技术架构与开发计划（Cocos Creator）

> 引擎版本：**Cocos Creator 3.8.x**，TypeScript，2D 项目（2.5D 俯视角）。
> 目标平台优先级：微信小游戏 → Android/iOS → H5。
> **两条铁律**：① 核心玩法逻辑**不依赖 Cocos API**，可在 Node 环境无头运行；② 一切内容数据驱动，**AI 可参与自动创作**，由机器校验把关。

---

## 1. 技术架构总览

### 1.1 分层结构

```
┌────────────────────────────────────────────┐
│ 表现层：UI / 飘字 / 特效 / 音效               │  UIController, DamageTextPool, FXPool
├────────────────────────────────────────────┤
│ 引擎适配层（薄，唯一允许 import cocos 的层）   │  CocosAdapter: 渲染/输入/音频/节点池
├────────────────────────────────────────────┤
│ 战斗层（零引擎依赖，纯 TS）                   │  WeaponSystem, ProjectileSystem,
│            纯逻辑 + Entity-Component         │  MonsterSystem, AssistSystem, BuffSystem
├────────────────────────────────────────────┤
│ 系统层（零引擎依赖，纯 TS）                   │  TargetingSystem, SpatialHash, Pool,
│                                            │  EventBus, WaveDirector, WallSystem
├────────────────────────────────────────────┤
│ 数据层：JSON 配置表（武器/怪物/卡牌/关卡/波次）│  DataTable + JSON Schema 校验
└────────────────────────────────────────────┘
```

### 1.2 核心设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| **引擎解耦** | 核心玩法零 Cocos import；引擎只通过 Adapter 接入 | AI 自动创作/自动测试的前提；引擎升级或更换不伤逻辑 |
| 架构模式 | 组件化 Entity-Component + 纯逻辑 System | 不做 ECS 框架（团队成本高），逻辑与表现分离，便于测试 |
| 数据驱动 | 全部数值/词条/波次表走 JSON 配置 + JSON Schema 校验 | 热更调数值；AI 生成的内容可被机器校验 |
| **帧模型** | 固定步长逻辑帧（30Hz tick）+ 渲染插值，逻辑确定性 | 同种子可无头复现，可回归测试，AI 模拟可 100 倍速跑 |
| 性能基线 | 同屏 200 怪 + 300 投射物 60fps（小游戏 30fps 兜底） | 对象池 + 空间网格是硬要求；几何渲染天然轻量（见 06） |
| 存档 | 本地 JSON（localStorage / 小游戏 wx.setStorage）+ 版本号迁移 | 先单机，预留云存档接口 |
| 事件通信 | 轻量 EventBus（on/off/emit）+ 战斗层直接调用 | 避免全事件化难调试 |

### 1.3 关键模块职责

逻辑层模块只操作纯数据实体，不碰 cocos 节点；表现由适配层监听逻辑状态渲染。

- **Entity/Component**：实体 = id + 组件数据（纯对象），如 `Monster { hp, def, speed, behavior, wallDps... }`。
- **Pool（对象池）**：逻辑层管"激活/回收"状态，适配层管节点复用。
- **SpatialHash（空间网格）**：怪物按 64px 网格注册，供索敌、分离、AOE 查询。
- **DamagePipeline**：01 文档公式落地；纯函数 `calcDamage(attacker, target, skill) → result`。
- **Trajectory 组件库**：Straight / Parabola / Boomerang / Homing / Chain / Orbit，配置化组装。
- **WaveDirector**：读关卡波次表，驱动 prepare → spawning → clear → intermission 状态机；波内构成变体随机。
- **WallSystem**：城墙实体、城防血条、受击反馈、城破/胜利判定与星级结算。
- **CardSystem**：升级三选一（权重、保底、过滤、重roll）。
- **SaveManager**：局内快照（暂停恢复）+ 局外元进度。

### 1.4 目录结构建议

```
assets/
├── scripts/
│   ├── gamecore/    ★零引擎依赖：entity, system, ai, damage, trajectory,
│   │                  targeting, wave, card, wall, buff, math, save
│   ├── adapter/     ★唯一 import 'cc' 的层：render, input, audio, tween-fx, pool-impl
│   ├── ui/          (HUD, 三选一卡, 结算, 引导)
│   └── meta/        (局外养成, 图鉴)
├── configs/         (json + schema: weapons, monsters, cards, levels, waves)
│   └── art-style/   (色板 / 形状 / 动效规范，美术与程序共用)
└── prefabs/         (cocos 表现预制体，纯视图，无逻辑)

tools/               ★Node 脚本，不依赖引擎：
├── sim/             (无头模拟整局战斗 + 人工轨迹回放 --replay，输出 DPS/TTK/城破压力报告)
├── validate/        (JSON Schema 校验 + 数值规则校验)
└── aigen/           (AI 内容生成流水线入口：prompt 模板 + 生成 + 校验 + 报告)
```

### 1.5 引擎解耦架构（约束与适配）

**硬约束**：`gamecore/` 内禁止 `import ... from 'cc'`——ESLint `no-restricted-imports` 门禁，CI 拦截。

**适配接口**（逻辑层定义抽象，适配层实现）：
- `IRenderer`：实体出生/移动/销毁/动画状态事件 → CocosAdapter 用节点表现（几何绘制见 06 规范）
- `IInput`：触屏拖动/虚拟摇杆 → 逻辑层只收到 `{ moveDir, delta }`
- `IAudio / IEffect`：逻辑层只发事件（`onHit`/`onExplode`/`onWallBreak`），音效粒子由适配层播放

**收益**：整个游戏可在 Node 里以 100 倍速无头跑完一局，这正是 AI 生成内容时自动评估质量的基础设施。

**单数据源原则**：逻辑层是唯一真相；渲染层只读逻辑快照 + 事件，**禁止表现层回写逻辑**（防两套状态漂移）。

### 1.6 AI 自动创作流水线

```
① 人类给设计意图（例："第 2 章需要 2 种克制弹幕流的怪，磨墙能力强但怕 AOE"）
② AI 生成候选内容 JSON（怪物/武器/卡牌/波次表，严格符合 JSON Schema）
③ 机器校验：Schema 校验 + 规则校验（引用完整、数值范围、id 唯一、对墙 DPS 预算）
④ 机器试玩：sim 无头跑 N 局（多种 AI 走位策略 × 不同构筑），输出报告：
   - 城破率 / 通关率 / 平均剩余城防 / 平均星级
   - 卡牌选取率分布、各武器 DPS 贡献占比
   - 构筑维度：`--weapons a,b`（初始组合）/ `--acquire 60:id`（到点获得新武器，模拟升级卡入手时机）/
     `--no-pool`（关闭三选一新武器候选，复现旧口径）
   - 每波 TTK 与"潜在对墙 DPS"校验
   - 真人基线：web 端自动录制人工走位（traces/*.jsonl，逐 tick 输入流 + 选卡），
     `sim --replay` 逐位复现——人工轨迹持续积累，作为 AI 走位标定/模仿学习的对照样本
⑤ 达标自动入库 configs/；不达标附报告打回 AI 重生成（最多 3 轮后转人工）
⑥ 人类只做：意图评审 + 试玩报告抽检 + 手感终审
```

权限边界：**AI 只许改 `configs/`，不许改 `gamecore/`**；schema 不过的内容，游戏加载时直接报错拒绝。

## 2. 开发里程碑（12 周计划）

### M1 原型验证（第 1~3 周）
- **第 1 步（无头）**：`gamecore` 骨架 + sim 工具——Node 命令行模拟一局 3 波防守（胜利/城破两路径），输出数值报告
- **第 2 步（接管渲染）**：CocosAdapter + 单屏场景 + 底部防守区域移动（矩形钳制）+ 城墙实体与血条
- 1 种武器（子弹）自动索敌发射 + 对象池；1 种怪（march，驻留磨墙）+ 经验宝石 + 三选一（仅属性卡）
- 波次导演 v1：3 波固定波次（prepare → spawning → clear → 休整）
- **验收**：同种子下 sim 报告与真实对局数值一致；胜利/城破两条路径跑通；60fps

### M2 核心循环完整（第 4~6 周）
- 4 种 MVP 武器全实现（轨迹组件库、追踪、穿透）
- 3 辅助单位（跟随 AI + 自带武器）+ 武器进化系统
- 怪物 6 种（dash/ranged/splitter/assault_wall）+ 精英词缀 + 完整波次导演（10 波/关 + 休整）
- 卡牌系统完整（稀有度/权重/保底/紧急修城卡）
- **AI 流水线 v1**：波次表自动生成 + 校验 + sim 报告全链路打通
- **验收**：一局 10 分钟割草爽感成立；同屏 150 怪不掉帧；AI 产出的 10 份波次表全部过检入库

### M3 内容与 Boss（第 7~9 周）
- Boss（三阶段）+ Boss 关 + 精英关
- 第 1 章全部关卡（6 普通 + 1 精英 + 1 Boss）+ 胜利/城破结算、星级、章节解锁
- 局外：金币升级英雄属性、武器解锁、图鉴
- 性能专项：小游戏包体裁剪、几何绘制合批（Graphics 静态批处理/精灵合批）
- **验收**：可对外测试的封闭 Beta；第 1 章波次表 ≥80% 由 AI 流水线产出且全部过检

### M4 打磨与发布准备（第 10~12 周）
- 新手引导（前 3 分钟）、UI/动效/音效打磨（动效按 06 规范参数精调）
- 数值平衡（sim 批量回归 + 人工 20 局）
- 微信小游戏适配（性能、包体 < 30M 主包）、提审
- **验收**：通过冒烟测试 + 提审通过

## 3. 风险与对策

| 风险 | 对策 |
|------|------|
| 引擎 API 渗入核心逻辑，解耦烂尾 | ESLint 禁 import 门禁 + CI 拦截 + Code Review checklist 首条 |
| 逻辑/表现状态漂移（两套真相） | 单一数据源在逻辑层；渲染只读快照 + 事件驱动，禁回写 |
| AI 生成内容数值穿帮 | sim 试玩报告硬门槛 + 人类抽检；AI 仅可改 configs/ 的权限边界 |
| 数值失衡导致割草不爽 | sim 无头模拟先于人工调参；波次表提交必附报告 |
| 配置表膨胀难维护 | schema 冻结评审（策划/程序/数值三方），工具校验 |
| 小游戏性能 | 几何图形渲染天然轻量；提供"流畅模式"画质档（减粒子/拖尾） |
