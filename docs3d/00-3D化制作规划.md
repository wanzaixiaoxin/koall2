# 《英雄守卫战 3D》制作规划（docs3d/00）

> 分支：`feature/3d-gameplay` · 基于 main @ 93456fc
> 定位：**复用 2D 确定性逻辑内核，做一次"视觉与操控的三维化重制"**
> 类型：3D 竖屏（人视角）守卫射击 Roguelike
> 引擎：Three.js r170（WebGL2）+ 现有 gamecore（零修改）+ 新 3D 适配层

---

## 0. 制作宣言：3D 化的三个决定

1. **逻辑内核一行不改**。`src/gamecore/` 的确定性 30Hz 会话、事件总线、索敌/轨迹/伤害全是资产
   ——3D 适配层只消费只读快照与事件（与 web 2D 适配层同一契约）。任何"3D 才需要的逻辑"
   一律放适配层（如镜头跟随、拖尾），污染内核 = 回归。
2. **视角决定玩法表达**：用**人类第三人称跟随视角**（镜头在英雄身后上方、略俯视战场纵深）。
   怪物从远处地平线压来 → 近景压迫感，这是 2D 俯视给不了的"潮水感"。
   怪物仍从"远方"生成（逻辑层 spawnBandY 远端），只是镜头让远方看起来在"地平线"。
   **跟随镜头意味着玩家看不到全图，漏怪压力变大——这是有意的设计张力**（用威胁指示器补足信息，见 §1.3）。
3. **美术仍走"优雅几何"**：全部几何体+光照+粒子，零位图素材（延续 docs/06 规范）。
   低多边形几何怪 + 体积雾 + 边缘光，追求"风格化低模+霓虹"而不是"伪写实"。

## 1. 玩法逻辑：3D 化后什么变了，什么没变

### 1.1 不变的（逻辑层原样）

| 系统 | 说明 |
|------|------|
| 战斗会话 | 30Hz、确定性、种子可复现——可回归对比 2D 版行为 |
| 武器/投射物/轨迹 | 开火→投射物→扫掠碰撞→伤害结算，全在 2D 逻辑平面（x=横, y=纵深） |
| 怪物 AI | 行军/闪走/冲锋/远程/分裂/钻地/自爆/虫苔等全部行为 |
| 波次导演 | 固定波次表、战备/清场/波间状态机 |
| 卡牌三选一 | 升级构筑循环不变 |
| 城墙防守 | 城防血条、城破判定、星级 |
| 伤害类型/弱点/抗性 | 五系伤害克制表不变 |

### 1.2 变了的（适配层表达，不动内核）

| 维度 | 2D | 3D 版表达 |
|------|----|----|
| 操控 | 指针/WASD 在矩形区域移动 | **WASD/左摇杆前后左右移动；英雄朝向插值** |
| 视角 | 正交俯视，全战场可见 | **跟随镜头**（英雄身后上方，看向英雄前方约 40% 战场深度处），可见范围收缩→漏怪压力变大（有意的设计张力，威胁指示器补足） |
| 投射物 | 2D 平面飞行的圆点/箭头 | **3D 光弹+拖尾**：子弹是发光小球/箭矢 mesh + 加法混合拖尾 |
| 怪物 | 2D 形状语言 | **低模几何体 + 简易程序动画**（史莱姆压扁/狼前倾/Boss 浮游+触手旋转） |
| 城墙 | 一条血条+砖纹 | **3D 城墙体块**：石砖段墙 + 城门洞，受击时该段砖块闪红+碎屑粒子 |
| 粒子/特效 | Canvas 加法混合 | **GPU 粒子（Points + 自定义 shader）**：命中火花、爆炸火球、经验宝石吸附 |
| 音效 | 无 | （阶段 6）WebAudio 合成音效（零素材：振荡器+噪声缓冲） |

### 1.3 3D 玩法增强点（本作 3D 版的灵魂，写进验收标准）

1. **纵深压迫**：镜头贴英雄、怪物从雾中浮现 → 必须靠**威胁指示器**（墙前危险方向箭头/屏幕边缘红光）补足信息。阶段 3 落地。
2. **威胁感知三件套**（阶段 3 验收）：漏怪侧向提示（屏幕边缘方向红光）+ 城墙受击方向指示 + Boss 出场横移镜头。

## 2. 场景搭建（阶段 2 细案）

战场是一块 1080×1920 的逻辑平面映射到 1:1 米单位 3D 地面（x=横，z=纵深，逻辑 y → 3D -z）。
逻辑坐标 → 3D 世界：`X = x - W/2`, `Z = -y`（墙在 z≈0 附近，怪出生在 z≈-1800 附近）。

- **地面**：大平面 + 程序网格纹理（Canvas 生成：暗蓝黑底 + 青色网格线，同 2D 版 body::before），防守区（yMin~yMax）用青色发光边界框标出。
- **防守区边界**：半透明青色边界栏（三个方向），只挡英雄不挡怪物/子弹，受击时闪烁。
- **城墙**：整排 BoxGeometry 石砖墙（含城门洞），横跨战场全宽；逻辑高度 64px → 3D 高 3.5m（表现层自由度）。
- **天空**：渐变天空穹顶（ShaderMaterial：夜空深蓝→地平线暗红）+ 星点（Points）。地平线方向（怪物来向）有"裂隙"发光带——叙事感：怪物从空间裂隙涌出。
- **雾**：`THREE.Fog` 从地平线吞掉出生带，怪物浮现时先见剪影。
- **光照**：环境光(弱) + 月光平行光(青白) + 英雄提灯光(暖色点光源跟随英雄) + 武器枪口闪光(短促点光)。
- **宝石/血瓶掉落**：旋转的八面体（青=经验、红=血瓶），落地弹跳，英雄靠近吸附飞向英雄。

### 2.1 性能预算（1080p 桌面）

- 同屏怪物 ≤ 120 可见（逻辑层照常生成 300，渲染层只画视锥内+近墙的——**视锥裁剪是 3D 版性能生命线**）；
- 绘制调用 ≤ 350：怪物 InstancedMesh 按形态分池，投射物单 InstancedMesh，拖尾用线束；
- 目标 60 FPS；桌面 Chrome。移动端为后续里程碑。

### 2.2 视觉展现（阶段 2-3 视觉验收）

- **构图**：镜头默认（pitch ≈ -35°，距离 14m，高 8m），英雄位于屏幕下 1/3；怪物从雾中地平线涌来。
- **色板**：沿用 palette.json（夜空 #07080F / 主青 #35E0C3 / 警示红 #FF6B57 / 暖橙 #FF9A3C / 黄暴击 #FFD54F）。
- **怪物形态语言**（低模几何，docs/06 形状语言 3D 转译）：slime→压扁 icosahedron（squash&stretch）；wolf→锥体前倾（冲锋拉伸）；thrower→立方体+细长矛锥；boss→浮游大八面体+环绕卫星体+锥体链触手。
- **特效语言**：命中=火花粒子+闪白（emissive 脉冲）；爆炸=火球+冲击环+地面弹坑印；落雷=天空光柱；治疗=绿色上升粒子；墙受击=砖屑+墙段红闪+屏幕边缘红晕。
- **伤害飘字**：3D→屏幕投影飘字（HTML overlay），沿用 2D 版事件与池化（上限 40）。
- **HUD**：沿用 2D 版 HUD 结构（城防条/经验条/波次横幅/卡牌三选一 overlay），样式微调适配宽屏。

## 3. 里程碑划分（每阶段完成即备份 tag + docs3d 阶段日志）

| 阶段 | 内容 | 验收 |
|------|------|------|
| P1 技术验证 | Three.js 接入 + 会话驱动 + 基本场景（地面/雾/城墙/英雄胶囊+提灯）+ 镜头跟随 + WASD 移动 | 逻辑会话跑通；逻辑坐标映射验证（墙位/出生带/防守区 3D 位置正确） |
| P2 战斗表现 | 怪物 InstancedMesh 池 + 投射物光弹+拖尾 + 命中/爆炸/落雷特效 + 伤害飘字(投影) + 城墙受击反馈 | 一局完整战斗可视：割草感成立，60fps |
| P3 玩家体验补全 | 威胁指示三件套 + 宝石掉落/吸附 + 波间休整表现 + HUD 宽屏化 + 开始/结算画面 | 一局从开始到结算零文档可玩，威胁感知成立 |
| P4 平衡与打磨 | sim 回归（3D 版逻辑与 2D 同种子对比）+ 数值/手感微调 + fx-config 3D 转译接线 | sim 报告与 2D 基线一致（同种子同结果）；手感可玩性通过玩家测试 |
| P5 迭代环 | 制作人→玩家双角色评审 → 提意见 → 迭代，循环至 token 耗尽 | 每轮迭代有评审记录 + 改动清单 + 备份 tag |

**每阶段完成动作**：`git tag backup/pX-<desc>` + docs3d 阶段日志 + 归档。

## 4. 技术架构（3D 适配层）

```
src/adapter/web3d/           唯一 import 'three' 的层
  main.ts                    启动/加载配置/会话/主循环
  scene/world.ts             场景搭建（地面/墙/天空/雾/光）
  render/
    hero-render.ts           英雄胶囊+提灯+朝向
    monsters-render.ts       怪物 InstancedMesh 池（按 shape 分池）
    projectiles-render.ts    投射物光弹+拖尾
    fx3d.ts                  粒子特效运行时（命中/爆炸/落雷/治疗）
    floats.ts                3D→屏幕投影飘字
  camera-rig.ts              跟随镜头（位置/朝向/震动）
  hud.ts                     HUD 绑定（复用 2D 版 HUD 事件语义）
  input3d.ts                 WASD/指针输入
```

## 5. 风险与约定

| 风险 | 对策 |
|------|------|
| 3D 性能（同屏 300 怪） | InstancedMesh 分池 + 视锥/距离裁剪 + 粒子池上限 |
| 3D 下信息缺失（看不到全图） | 威胁指示三件套（阶段 3） |
| 逻辑坐标→3D 映射错位 | P1 验收专测：墙位/出生带/防守区对齐验证 |
| Three.js 版本 API 变动 | 锁定 r170 |

**硬约定**：
- 逻辑 y → 3D -z 的映射只在一处定义（`LOGIC_TO_3D`），禁止散落硬编码；
- gamecore 禁止 import 'three'（与既有"禁止 import 'cc'"门禁同性质）；
- 渲染层禁止回写会话状态（单一数据源约定延续）。
